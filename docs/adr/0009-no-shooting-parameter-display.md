# 0009: 撮影パラメータをビューアに表示しない

- 日付: 2026-08-09
- 状態: 採用

## 文脈

サーバーの `GET /api/media/{id}` は `exif` ブロック（`lens` / `iso` / `shutter` /
`f_number` / `focal_len` / `gps_*`）を返しているが、アプリのビューアはこれを
一度も読んでいない。2026-08-09 の全体レビューで「サーバーが返しているのに
表示していない」欠落として挙げ、旧 Progress A11 としてバックログに載せた。

その後サーバー側で値の埋まり方を確認したところ、取り込み経路によって差があった。

| 取り込み経路 | 撮影パラメータ |
|---|---|
| ローカル取り込み | 元ファイルの EXIF から埋まる |
| Google Photos 取り込み | **全て NULL**（`raw_json` のみ保存） |

ローカル取り込みでも、値は元ファイル次第（スクリーンショット・書き出し済み
JPEG・動画には最初から入っていない）。

## 決定

**ビューアに撮影パラメータの欄を作らない。** 旧 Progress A11 はバックログから
外す。

サーバー側の判断（`photonest` リポジトリの `docs/decisions/ADR-0027`）が
出所であり、本 ADR はそのアプリ側の帰結を記録するもの。表示の有無を SPA と
アプリで食い違わせない。

`AlbumSnapshotRepository` などのローカルキャッシュに撮影パラメータを持たせる
準備も行わない（表示しないものを端末へ保存する理由が無い）。

## 帰結

- ビューアが出す情報は、探すために要るもの（撮影日時・寸法・キャプション・
  タグ・お気に入り）に留まる。
- API 応答の `exif` ブロックは残るが、アプリはパースしない。`MediaDetail` 相当の
  エンティティに撮影パラメータのフィールドを足さない。
- **次のレビューでこれを「未実装の欠落」として再び挙げない。** 表示しないことは
  決めた結果である。
- 見直す条件は ADR-0027 と同じ（利用者から要望が出る／Google Photos 経路でも
  同じ項目が埋まるようになる）。サーバー側が表示へ舵を切ったら、本 ADR を
  差し替えてアプリも追随する。
