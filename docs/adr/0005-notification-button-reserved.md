# 0005: 通知ボタンを通知機能の予約済み入り口として残す

- 日付: 2026-08-07
- 状態: 採用

## 文脈

メインページのヘッダーに通知ボタンがあるが、タップしても何も起きない
（`lib/presentation/pages/main_page.dart` の `IconButton` が空の `onPressed`）。
旧 Progress #13 は「削除するか実装するか」の要判断タスクだった。

選択肢は 3 つあった。

1. **削除する** — 「押しても何も起きない UI」を残さない。ただし通知機能を
   後から足すときにヘッダーのレイアウト・l10n キー（`commonNotifications`）を
   作り直すことになる。
2. **いま実装する** — 通知の実体（何を・いつ・どこから通知するか）は
   バックグラウンド自動アップロード（Progress #4）の設計と不可分で、
   単独で先行実装すると手戻りになる。
3. **予約済みの入り口として残す** — ボタン・l10n キーを維持し、
   通知機能の実装時にそのまま配線できる状態を保つ。

## 決定

**3. 予約済みの入り口として残す。**

- ヘッダーの通知ボタンと `commonNotifications` の l10n キー（en/ja）は
  削除しない。通知機能を実装するときは、このボタンの `onPressed` に
  通知一覧への遷移（または通知パネルの表示）を配線する。
- 通知機能そのものは別タスクとし、バックグラウンド自動アップロード
  （Progress #4）の設計と合わせて「アップロード完了・失敗の通知」を
  第一のユースケースとして扱う。
- それまでの間、このボタンが no-op であることは本 ADR を根拠とする
  （「消し忘れ」「実装漏れ」ではない）。

## 影響

- 影響範囲: `main_page.dart` のヘッダー 1 箇所と l10n キー。コード変更なし。
- 通知機能の実装タスクは Progress のバックログ（#4 と関連）で管理する。
- ボタンの no-op が利用者の混乱を生むようであれば、実装までの暫定として
  「通知はまだありません」の表示を配線する軽量な選択肢もある（本 ADR の
  決定を変えずに追加できる）。
