## 詳細

1. **A6 — アルバムの作成と編集。** 今は一覧と詳細の閲覧だけ
   （`AlbumRepository.findAll` / `findById`）。作成は
   `POST /api/albums`、更新は `PUT /api/albums/{id}`、いずれも
   `album:create` / `album:edit` scope が要る。
   **収録メディアは差分ではなく `mediaIds` の全置換で送る。**
   `POST /albums/{id}/items` のような追加専用のエンドポイントは無い
   （旧 A5 のメモはここを取り違えていた）。「この写真をアルバムへ入れる」を
   作るなら、対象アルバムの現在の収録を全ページ読んでから 1 件足した配列を
   PUT することになる——大きいアルバムでは往復が増えるので、詳細ビューアから
   の導線を作るかは、その代償を見てから決める。
   境界は A3・タグと同じ形を使える（閲覧の repository とは分ける・結果は
   読み込み済みの状態へ書き戻す・サーバーが確定した値を採る）。
   画面が要る（作成フォーム・編集フォーム）ぶんタグより重い。

2. **A7 — アカウント設定。** プロフィール／パスワード変更・TOTP・パスキー。
   いちばん後に置く——写真を見ている最中に必要になるものではなく、
   Web の管理画面でできる。パスキー（`/api/auth/passkeys`）は端末側の
   WebAuthn 対応が要るので、ここだけ切り出して判断する。

## メモ（実装済みタスクの運用上の注意）

- **release 署名のフィンガープリントが未記入。** `docs/deep_links/assetlinks.json`
  は `package_name` と debug 署名の指紋まで入っているが、release 分は
  `REPLACE:WITH:YOUR:RELEASE:KEYSTORE:SHA256:FINGERPRINT` のまま。鍵を持つ人が
  `docs/DEEP_LINKS.md` の手順で埋め、サーバーの管理画面
  （Domains & URLs > Android アプリリンク）へ貼るまで、release ビルドの
  App Link は検証されずブラウザで開く。Play App Signing を使う場合は
  アップロード鍵ではなく Play Console の「アプリの署名鍵の証明書」の指紋を使う。
- `minSdk` は 31。App Links の intent filter が `android:pathAdvancedPattern`
  （API 31 以上）でパスを厳密に絞っているため、下げるならパス指定の書き換えが
  先。API 30 以下の端末はこの属性を無視し、filter がホスト全体へ静かに広がる。
- ローカル DB のファイル名は `flutterbase.db` のまま（`AppDatabase.fileName`）。
  端末内部の名前で画面にも API にも出ないため、改名しても得が無く、既存
  インストールのローカルデータを捨てるだけになる。
- サムネイルは署名付き URL の一括発行（`POST /api/media/thumb-urls`）で取る
  （A2）。束ねているのは `ThumbnailUrlBatch` で、同じフレームで求められた
  ぶんが 1 リクエストになる。発行できない・失敗する・URL が期限切れの場合は
  アプリサーバー経由（`GET /api/media/{id}/thumbnail`）へ落ちるので、
  単発のエンドポイントは今後も要る。
- 写真タブの絞り込み（A1）は `libraryMediaQueryProvider` が持つ。変わると
  タイムラインは**先頭の窓から**読み直す——前の絞り込みで取ったカーソルは
  別の結果集合を指しているため。検索欄の待ちは `mediaSearchDebounce`。
- お気に入りの結果はサーバーが確定した値を採る（A3）。別端末が先に変えて
  いた場合、押した側の期待ではなく保存されている値が画面に出る。
- タグの付け外しには `media:tag-manage` scope が要る。持っていないユーザーは
  エディタを開いて選べるが保存で 403 になる（サーバーが scope を持たない
  ことを事前に知らせる手段が無いため）。剥奪する場合は管理画面のロール権限
  編集で変更する。
- タグエディタは保存するまで何も送らない。開いている間に別端末が同じ
  メディアのタグを変えていた場合、後から保存した側の集合で上書きされる
  （エンドポイントが差分ではなく全置換のため）。
- タグの新規作成はアプリから行えない。既にライブラリにあるタグの付け外し
  だけで、`POST /api/tags` は呼んでいない。新しいタグは Web の管理画面で
  起こす。
- ゴミ箱からの復元はタイムラインを触らない。撮影日時順のどこへ入るかを
  推測せず、次の読み込みに任せる。
- ゴミ箱の一覧（`trashedMediaProvider`）は `autoDispose`。まもなく完全に
  削除されるものの一覧を持ち続けても古くなるだけなので、画面を出るたびに
  忘れる。
