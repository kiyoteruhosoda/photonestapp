# 0011: 自動バックアップの対象を端末アルバムで選ぶ

- 日付: 2026-08-09
- 状態: 採用

## 文脈

自動バックアップは端末のライブラリ**全体**を対象にしていた。
`PhotoManagerPhotoLibraryGateway.photosTakenAfter` は `onlyAll: true` かつ
`RequestType.common` で問い合わせるため、対象は「有効化以降に作られた
すべての静止画と動画」になる。

つまり次のものが、利用者が一度も選んでいないのに NAS へ上がっていた。

- スクリーンショット
- メッセージアプリが受信して保存した画像
- 保存したミーム・ダウンロードした画像
- 画面録画・受信した動画（**動画も対象**であることは見落としやすい）

結果として、サーバー側のライブラリが実際に撮った写真ではないもので埋もれ、
回線とストレージも食う。「保存した写真を見る」が、保存しすぎたことで
困っている状態にあたる（`CLAUDE.md`「プロダクトの範囲」の 1 に照らして
実際に困っているのはこれ）。旧 Progress A10。

## 決定

**端末側のアルバム単位で、自動バックアップの対象を選べるようにする。**

- 既定は「この端末のすべて」——既存インストールの挙動は変わらない。
  設定が保存されていない状態と「すべてに戻した」状態は同じ形（空集合）で
  持ち、読み分けない。
- 選択はアップロードタブの既存カードに 1 行足し、**ダイアログ**で選ばせる。
  画面（ルート）は増やさない。写真を見るまでのタップ数は変わらない。
- 選択は端末アルバムの id で覚える。アルバム名の変更・件数の増減で選択が
  外れない。**存在しなくなったアルバムの id も残す**——外部メディアの
  取り外しのような一時的な理由で対象が黙って広がるのを避ける。
- 対象は**自動**バックアップだけに掛かる。アップロードタブのグリッドから
  手で選んで送る経路は、その時点で利用者が選んでいるので絞らない。

### 「充電中のみ」は入れない

A10 には「合わせて『充電中のみ』の条件も検討する」と書いてあったが、
**入れない。**

- 上のような取りこぼしを起こしているのは*対象の広さ*であって、実行の
  タイミングではない。対象を絞れば、送る量そのものが減る。
- 「保存する」の側を実際に困らせている証拠が無い。バッテリー消費の苦情も、
  自動バックアップが電池を切らしたという記録も出ていない。
- 条件を足すと「上がっていない理由」が増える。今は Wi-Fi と権限の 2 つで
  説明が付くところに 3 つ目が入り、利用者から見て**保存に失敗しているのか
  待っているのか**が分かりにくくなる。

`CLAUDE.md`「機能を足すときの制約」1（既定は作らない）に従い、必要性が
示せるまで作らない。

## 帰結

- `PhotoLibraryGateway` に `albums()` が増え、`photosTakenAfter` は
  `albumId` を取る。null は従来どおりライブラリ全体で、既定の経路の
  問い合わせ回数は変わらない。
- 複数の選択アルバムに同じ資産が入っていることがある。アップロード履歴は
  パスが終わってから書かれるので、**パスの中で重複を落とす**
  （`SyncNewPhotosUseCase`）。
- 選択を狭めても、すでに上がったものは消えない。狭めるのは「これから送る
  もの」の話。
- **次のレビューで「充電中のみが無い」を欠落として再び挙げない。**
  見直す条件は、電池の消費が実際に問題として出てくること。
