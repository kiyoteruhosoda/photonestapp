# 0014: アカウント画面は「入り口を保つ」ものだけを扱う

- 日付: 2026-08-10
- 状態: 採用

## 文脈

アカウント設定をアプリへ入れた（旧 Progress A7）。ADR-0010 は A7 を
**「自分のライブラリへの入り口を保つ手当（パスワード・二要素）」**として範囲の
内側に置いている。Progress にも「設定タブに 1 画面足す形にとどめ、Web の
管理画面と同じ密度の画面をアプリへ持ち込まない」と書いてあった。

サーバー側にある「アカウント」まわりの API は次のとおり。

| 対象 | エンドポイント |
|---|---|
| プロフィール更新（email / username / password） | `PUT /api/auth/profile` |
| 二要素の状態・開始・確定・解除 | `GET|POST /api/auth/2fa/*`, `DELETE /api/auth/2fa` |
| パスキー | `GET /api/auth/passkeys` ほか |

## 決定

**アプリのアカウント画面はパスワード変更と二要素認証だけを扱う。**
メールアドレス・表示名・パスキーは入れない。

### メールアドレスを入れない

`PUT /api/auth/profile` は `email` を受け付けるが、これは**ログイン識別子**で
あり、変えた瞬間に次回のログインが変わる。端末に保存済みのセッションが持つ
`email` は表示用のコピーなので、変更後は食い違う。**「保存する」「見る」の
どちらも今それで困っていない**（家族が使う端末で、メールアドレスを変えたい
場面は観測されていない）。Web の管理画面で足りる。

### 表示名（username）を入れない

`PUT /api/auth/profile` は `username` を受け付けるが、**読み出す手段が無い**。
`GET /api/auth/me` は `username or email` を返す仕様で、未設定のときは
メールアドレスが返る。つまりアプリは「表示名が未設定」と「表示名が
メールアドレスと同じ」を区別できない。入力欄を置けば、未設定の人には
メールアドレスが初期値として入り、保存した瞬間に表示名がメールアドレスで
確定してしまう。**読めないものは編集させない。**

### パスキーを入れない

端末側の WebAuthn 対応が要り、他と重さが違う（Progress でも「切り離して
判断する」としていた）。ブラウザの PhotoNest から設定できるので、画面には
**そこで設定できることだけを 1 行書く**——黙って消すと「アプリがパスキーを
失くした」と読めてしまう。

## 帰結

- **二要素を有効にできるようにする以上、ログイン側の対応が前提**である。
  サーバーの `POST /api/auth/login` は認証アプリ登録済みのアカウントに
  `401 totp_required` を返すため、`token` を送れないアプリは有効化した瞬間に
  次のログインから締め出される。同じ変更でログイン画面にコード欄を入れた。
  欄はサーバーが要求してから出す——持っていない人に埋められない欄を最初から
  見せない。
- 画面は `/account` の 1 枚だけ。設定タブのアカウントカードから 1 タップで
  開く（タブは増えない。ADR-0010「タブは 4 つを上限」の内側）。
- **パスワードは 2 回入力させる。** 見えない入力を 1 回で確定させると、
  打ち間違いが他の全端末からの締め出しになる。前後の空白は削らない
  ——ログインも削らないので、ここで削ると本人が入れなくなる。
- **二要素の登録は「秘密鍵を取得 → コードで確定」の 2 段。** 取得しただけでは
  サーバー側は何も変わらない。途中で閉じればアカウントはそのままで、次回は
  新しい秘密鍵から始まる。
- 登録の導線は `otpauth://` URI を**外部アプリで開く**のが第一。スマートフォン
  では認証アプリがそのまま登録でき、何も打ち込まない。セットアップキー
  （コピー可）と QR も併記する——QR は**別の端末から読む**ためのもので、
  表示している端末自身は自分の画面を撮れない。
- **サーバーは現在のパスワードを訊かない。** `PUT /api/auth/profile` は
  アクセストークンさえあれば `password` を書き換える。アプリはこの API に
  合わせており、確認入力はあくまで打ち間違い対策である。ここを変えるなら
  サーバー側の変更（と Web 管理画面の追随）が要るので、`photonest` 側の
  判断として起こす。
- 次のレビューで「サーバーに `/auth/profile` の email / username があるのに
  アプリから触れない」「パスキーが無い」を欠落として挙げない。触れないことは
  決めた結果である（ADR-0010 の制約 3）。
